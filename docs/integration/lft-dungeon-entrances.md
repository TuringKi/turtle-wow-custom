# LFT 全队自动进入副本

五名成员全部接受 LFT 邀请后，服务器先完成组队、检查全队，再将真人和机器人传送到同一个副本实例。`LFT.Teleport.Enable = 1` 启用；独立于随机机器人补位开关，也适用于五名真人的 LFT 队伍。`LFT.BotFill.SeedRuns = 0` 保持不启动纯机器人自行开队。

## 检查与失败处理

- 全员在线、已进入世界、存活，且不处于战斗、飞行、传送或战场/战场排队状态。
- 全员仍属于匹配出来的同一个五人非团队队伍，并且已全部接受邀请。
- 保留入口的等级（含核心既有特殊挑战规则）、阶段、任务/物品条件和进本次数检查。
- 拒绝冲突的永久进度；预先检查整个队伍的目标实例容量。先建立/复用一个实例并绑定队伍，再安排所有成员传送，不清除玩家永久进度。
- 已在目标实例的成员不会再次调用会断言的 `CanEnter`；在同一地图的另一实例内时强制执行跨实例传送。
- 无法确认落点或只有“血色修道院”“厄运之槌”等不明确分区时，排队阶段就会提示，避免发出无法兑现的入本邀请。
- 预检失败不会开始移动任何成员。传送仍经过核心的异步地图加载与客户端 ACK；预检之后的断线或核心拒绝不能当作成功抵达，日志只记录“已安排传送”。

有额外副本时，可配置 `LFT.Teleport.Entrance.<规范化名称> = <areatrigger_teleport ID>`。名称转小写、去 ASCII 标点/空格和开头的 the，例如 `LFT.Teleport.Entrance.deadmines = 78`。配置落点仍须位于有效的非团队副本内；不会接受大陆/战场/团队副本。

## 验证

`tests/playerbots/test_lft_party_teleport.py` 编译实际入口解析和全队传送函数，以 ASan/UBSan 覆盖 34 个参考名称/短码、分区、名称中冒号、全员确认、最后一名成员准入失败时全队不移动、进度/容量、统一绑定、同地图跨实例以及公主传送点。世界、数据库和网络边界使用替身，不冒充真实客户端验证。

原 LFT 匹配回归仍编译实际队列/职责/邀请/完成函数。编译、只读入口审计、隔离集成测试及安装证据保存在服务器私有目录 `/root/turtle-wow-startup-check/lft-party-teleport/`。


实际隔离服验证：五名新建的本地合成机器人完成 LFT 组队后，均自动进入死亡矿井（map 36），`DungeonMap::Add` 日志的实例 ID 全部为 **101**；随后存档也显示五人同处 map 36、同属队伍 2。正常退出码 0，未出现数据库结构错误或断言。此测试使用临时纯机器人种子来驱动队列，没有真实 1.18.1 客户端参与；生产种子仍关闭。

程序已原子安装到 `/root/turtle-wow-custom/.install/libexec/mangosd`，SHA-256：`fd3d28a179b94ccc22adaa8c044c62db9b4df3314fb0641547eaeb2486845a38`。生产配置启用 `LFT.Teleport.Enable = 1`，保留 `NB1181` 前缀及 `SeedRuns = 0`。原程序和配置分别备份为私有验证目录中的 `mangosd-before`、`mangosd.conf-before`，没有删除既有备份；没有操作生产数据库，也没有重启生产世界服。需要用户重启世界服加载新程序。
