# 机器人跟随玩家离开副本

玩家出本后，机器人仍留在副本内：LFT 的组满传送只处理入本，普通跟随则通过 MovementAction::MoveTo 寻找跨地图路径；它不能保证每个自定义副本都有可用的出口路线。

在现代 PlayerbotAI::DoNextAction 开始执行动作前增加出本检查。机器人仍在普通副本、同队真人主人已完成传送并位于非实例地图时，跟随或 wander 模式会通过正常 TeleportTo 跟到主人当前位置。使用现有机器人会话的 worldport ACK 和 AI Reset 完成转移，不伪造真人客户端确认。

检查会随 AI 更新重试：双方须在线、存活、非战斗、非登出、非传送、非飞行路线、非交通工具、非战场及战场排队；机器人还须能够移动。stay/guard 命令、外部测试管理、真人角色、机器人主人、不同队伍、团队及团队副本不会触发此逻辑。因战斗等暂时状态被阻止后，条件恢复即可再次尝试；死亡机器人不会自动复活。多人队伍按机器人当前跟随的真人主人决定出本，不因任意队员离开就拉走全部机器人。

此检查不限定从 LFT 组队，因此也适用于 rndbot group。仅处理副本到野外的跟随，不改变入本条件或副本进度绑定。玩家使用炉石回到野外后，同队跟随机器人也会离开副本。

验证：test_dungeon_exit_follow.py 编译实际生产函数并以 ASan/UBSan 检查成功出本、重复更新防重传、忙碌状态恢复后重试、传送拒绝后重试，以及身份、队伍和停留条件。test_summon_states.py 和 test_lft_party_teleport.py 回归通过。这些是有状态测试替身，不代表真实 1.18.1 客户端出本实测。

无需执行 SQL。安装新 mangosd 后，须重启世界服才会加载此逻辑；部署过程不重启生产进程，不改配置或账号、角色数据。
